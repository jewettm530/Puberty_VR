ORIGINAL R JATOS PROCESSING VS CURRENT PYTHON CONVERTER
=======================================================
Updated: 2026-10-14. This reflects scripts/setup/process_jatos_python.py.

Input names and subject/session identity
----------------------------------------
R: Original conversion accepted JSON paths individually and derived a worker or
   study identifier from JATOS metadata/filenames.
Python: The converter uses scripts/file_naming.py to infer a numeric subject
   and session from a recognized filename and/or parent folder. Its output
   naming is normalized to three-digit IDs, e.g. 005_plearning_1.csv.
   Unrecognized names or missing experiment blocks are skipped with a warning.
   If two JSON files map to the same subject/session, it raises an error rather
   than silently overwriting one of them.

Behavioral trial output
-----------------------
R: Output filenames were often based on REDCapId-workerId combinations, and
   could be inconsistent across participants.
Python: Canonical output files are saved under data/processed/plearning/ as
   ###_plearning_1.csv and ###_plearning_2.csv. The workerId field is
   normalized to subject_###_plearning_N. Session-specific trial columns are
   retained if present in the source JSON. 'learned' compares chosen vs winner.

Subject-info metadata summary
-----------------------------
R: Original workflow could overwrite the aggregate summary on each execution.
Python: Uses data/metadata/subject_info_summary.csv. For each newly processed
   subject/session pair, it replaces that pair's older metadata row, retains
   other existing rows and de-duplicates on (subjectId, plearning_num).
   This permits new-subject additions without dropping older subjects.
   If a subject's raw JSON is permanently deleted, earlier processed CSVs
   may still exist; review stale derived data manually before future analyses.

Folder input and portability
----------------------------
R: Generally called with file paths and depended on R packages.
Python: Called with no arguments, searches all JSON files recursively below
   data/raw/subject_data/. Explicit paths and --recursive are also supported.
   Shared project_paths.py avoids hardcoded user-home absolute paths.
   Python depends on pandas/numpy and the repository requirements.txt.

Master pipeline
---------------
Python: scripts/run_all_analyses.py runs the full dependency sequence after
new subjects are added. It captures stage status in
outputs/pipeline_run_status.json and runs age comparisons only when a genuine,
readable Excel workbook contains all analyzed subjects' classifications.
